Claude Code Plugin

session-handoff

Ends every working session with a document the next session reads first — so it resumes your work without re-deriving decisions, re-checking state, or repeating dead ends.

Version 0.2.1 License MIT Repository github.com/anish00700/claude-session-handoff

1The problem it solves

Long sessions end one of two ways: you run /clear, or the context window quietly fills up. Either way the next session starts blind. It re-reads files you already read, re-asks questions you already answered, and — the expensive one — sometimes retries the exact approach that failed three hours ago.

A handoff file fixes that, but only if it records what a repository cannot: intent, rejected options, decisions made out loud, and the tool quirks you discovered the hard way. Your commit history already covers the rest.

This plugin adds one skill that writes and maintains that file. It runs the git commands to verify state rather than trusting recall, records failed attempts alongside the reason they failed, and names what is deliberately not done — the three things that save the most time downstream.

2Before you start

Claude Code Any version with plugin support. Check with claude --version.
Git The skill runs git status, git log, and git worktree list to verify state. It works outside a repository, with less to go on.
GitHub access Only to fetch the marketplace, once. The repository is public — no token or SSH key needed.

3Install

Two commands, run from anywhere. Both are one-time.

1

Add the marketplace

This registers where the plugin lives. It clones the repository into your local plugin cache.

$ claude plugin marketplace add anish00700/claude-session-handoff Adding marketplace… Cloning repository, validating marketplace… ✔ Successfully added marketplace: claude-session-handoff
2

Install the plugin

The @ suffix names the marketplace to install from. It is required — without it, Claude Code searches every marketplace you have registered.

$ claude plugin install session-handoff@claude-session-handoff ✔ Successfully installed plugin: session-handoff@claude-session-handoff (scope: user)

Scope: user means it is available in every project on your machine, not just the current one. That is the right default for this plugin — a handoff is useful in any repository.

Verify

$ claude plugin list Installed plugins: ❯ session-handoff@claude-session-handoff Version: 0.2.1 Scope: user Status: ✔ enabled
Restart your session

Skills load at session start. If you installed while a session was running, start a new one before the skill becomes available.

4Using it

There is nothing to configure and no command to memorise. The skill activates on its own when a session is winding down — say any of these in plain language:

wrap up write the handoff hand this off I'm about to clear save state update the handoff

It also triggers when your context window is running low, which is the case that matters most — that is precisely when work is about to be lost and you are least likely to remember to ask.

Installed skills also appear in the slash-command list. Run /help in a session to see the exact name on your setup.

What happens

The skill reads any existing handoff first, runs git and gh commands to confirm the real state, then writes SESSION_HANDOFF.md to the directory you are working in. On later sessions it replaces that file rather than appending — carrying forward what is still open and dropping what got resolved. Handoffs never stack up.

It is not committed automatically

The file is written to disk and left untracked. Commit it if your team should see it, or add it to .gitignore if it is just for you.

It keeps CLAUDE.md pointing at the handoff

Claude Code auto-loads CLAUDE.md, but SESSION_HANDOFF.md has no special meaning to it — a handoff nothing points to is a handoff nobody reads. So after writing, the skill checks for a CLAUDE.md beside the handoff: it adds a short pointer if there is none, creates the file if it does not exist, and leaves it untouched if the handoff is already mentioned.

Target length is 60–120 lines: short enough that the next session actually reads it before starting, long enough to carry the decisions.

7Troubleshooting

SymptomCause and fix
The skill never triggers Skills load at session start. Restart, then confirm with claude plugin list that status is enabled.
Repository not found on marketplace add Usually a typo in the owner/repo. The correct source is anish00700/claude-session-handoff, and it is public — no credentials needed.
Two handoff skills appear You have both this plugin and a local copy in ~/.claude/skills/. Keep one: uninstall the plugin, or delete the local directory.
A project version should win A skill at <repo>/.claude/skills/session-handoff/ takes precedence inside that repository. Use this to keep a project-specific example.
The handoff states things that aren't true The skill verifies with git before writing, but it cannot verify claims about intent. Read it once and correct it — it is a normal Markdown file.

8Customising it

The plugin is three plain Markdown files. Clone the repository, edit skills/session-handoff/SKILL.md to change the section list or the writing rules, and edit reference/example.md to swap the worked example for one from your own codebase.

A team-specific example is the single highest-value change you can make — the skill matches the tone and granularity of whatever example it is shown. If you change the section list in SKILL.md, update reference/template.md to match; they are meant to stay in lockstep.

To distribute an internal variant, drop the edited skill into your repository at .claude/skills/session-handoff/ and commit it. Everyone who clones gets it with no install step, and it overrides the public plugin inside that repository.
